**Learned:** A mutex guards a section of code, not the variable, by agreement between goroutines. `result += n` is read/add/write, hence lost updates. WaitGroup is a counter of running goroutines. Mutex protects shared state; channels pass data.

Interfaces are decoupling: the handler depends on `TaskService`, not the concrete type, so tests pass a mock. Implicit satisfaction, full method set required, the interface limits what the caller can see.

`context`: cancelling closes `ctx.Done()`; goroutines stop only if they check it (cooperative). `select` on `Done()` makes waits interruptible and prevents blocked sends leaking goroutines.

Error handling: `%w` keeps the original error in a chain so `errors.Is` (sentinel match) and `errors.As` (type match, assigns the found error into the target) work through wrapping.

Channels: unbuffered synchronises, buffered decouples; `close` is an explicit signal from the sending side after all senders finish, never automatic; an unmatched send leaks a goroutine; don't `wg.Wait()` in the receiver before ranging.
